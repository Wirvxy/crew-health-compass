# Mission Environment API: Mars radiation history

For Taha Errassif (frontend), from Monssif El Haouari (backend). Two read-only endpoints serve Iliass Barrou's R1 engine (`engine/radiation_history.py`, guide: [engine/RADIATION_HISTORY.md](../engine/RADIATION_HISTORY.md)). They return the engine's JSON unchanged.

**What the data is:** historical absorbed dose **rates** (µGy/day) measured by the Radiation Assessment Detector (RAD) on NASA's Curiosity rover, on the Martian surface, from 2024-03-07 to 2024-05-20.
- It describes the Martian radiation environment. It is **not** a personal astronaut exposure or a medical risk.
- It never affects Mode 1 or Mode 2.

## Start the backend

Same as before (see the [root README](../README.md#run-it-locally)). At startup the API reads `data/radiation/nasa_curiosity_rad_2024-03-07_to_2024-05-20.csv` once; set `CREW_HEALTH_RAD_CSV` to use another file. Nothing is downloaded.

## Endpoints

Both use the `/api` prefix, so Vite's dev proxy already forwards them.

| Method | Path | Query parameters (all optional) |
|---|---|---|
| GET | `/api/environment/radiation/timeline` | `start_date`, `end_date` (inclusive UTC dates, `YYYY-MM-DD`), `detector` (only `E` in this CSV), `include_statistics` (`true`/`false`, default `false`) |
| GET | `/api/environment/radiation/events/may-20-2024` | `detector` |

- **Timeline without filters:** all 5,971 readings (about 1.5 MB). Request it once and filter on the client, or ask for a date range.
- **Range with no readings:** a valid range that contains no readings returns `observation_count: 0`. This is not an error.

## Fields to use

**Timeline** (`/timeline`):

| Field | Meaning |
|---|---|
| `unit` | `"µGy/day"`: a dose **rate**, not an accumulated dose |
| `observation_count` | Readings in the response |
| `series[]` | One entry per detector: `detector`, `start_timestamp_utc`, `end_timestamp_utc`, `observation_count`, `observations`, `statistics` (null unless `include_statistics=true`) |
| `series[].observations[]` | `timestamp_utc` (e.g. `"2024-03-07T00:14:58.000Z"`), `value` (decimal **string**, or `null` for a missing or invalid reading), `value_status` (`valid`, `missing`, `invalid`), `raw_value`, `source_line`, `nasa_cdf_url` |
| `series[].statistics` | `observation_count`, `valid_count`, `missing_count`, `invalid_count`, `min`, `max`, `mean`, `median`, `first_to_last_change` (decimal strings), `peak` (one observation) |
| `source` | `csv_file`, `csv_sha256` (`d514a88f…`), `dataset_url` |
| `limitations` | Text to show with the chart |

**May 20 event** (`/events/may-20-2024`):

| Field | Meaning |
|---|---|
| `title`, `description`, `source_reference` | Event card text and the NASA link |
| `evidence_available` | `true` when the CSV has valid readings that day; use it to show or hide the numbers |
| `series[].statistics` | May 20 readings: `median`, `mean`, `peak.value`, `peak.timestamp_utc` |
| `series[].preceding_week_comparison` | `start_date`, `end_date` (May 13–19), `median`, `event_median_to_prior_median_ratio`, `valid_sample_count` |
| `limitations` | Includes that the extract **ends on May 20**, so the event's later duration is not covered |

**How to display the values:**
- Numbers are decimal strings. Convert them only to draw.
- Keep the raw strings for tooltips.
- Draw a `null` value as a gap, and leave visible gaps where readings are far apart.

## Errors

| Status | When | Body |
|---|---|---|
| 422 | Bad date format, impossible date, or `start_date` after `end_date` | `{"detail": "Invalid date filter: ..."}` |
| 404 | Unknown detector | `{"detail": "Unknown detector 'Z'. Available detectors: E."}` |
| 503 | The CSV was missing or unreadable at startup (no server path is shown) | `{"detail": "Radiation history not found. ..."}` |

Exception: if `include_statistics` is not a boolean, FastAPI returns 422 with a **list** in `detail`. The other tabs keep working when these endpoints return 503.
